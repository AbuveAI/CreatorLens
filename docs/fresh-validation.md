# 在新 Codex 项目中验收

目标：确认一个全新用户不依赖维护者旧项目，也能安装、运行并得到报告。

## 建立干净环境

从公共源码ZIP解压或克隆发布后的仓库，作为新的 Codex 项目。另建独立工作区。不要复制旧项目的依赖目录、配置、会话、媒体或报告。让 Agent 阅读 README、AGENTS 和项目 Skill，再按本文操作。

可直接发给新项目的 Agent：

> 请验证 CreatorLens。先阅读项目接手文档，使用本项目源码旁边的全新外置工作区。先离线 demo、检查示例报告，再安装固定版本 Spider_XHS 并运行测试和 doctor。不要访问其他项目的私有配置。等我给出目标后再做真实采集。每一步报告实际结果，不把离线测试当作线上成功；ASR及飞书仅在我明确选择后启用。

## 第一层：无需账号、无需付费

1. `init-workspace` 后确认 `asr.enabled` 和 `feishu.enabled` 都为 false。
2. `demo` 应返回两个自制图文样本、完整本地报告路径，且明确 `synthetic: true`。
3. 打开 Markdown 和 HTML，检查中文、六节内容、局限、逐图说明与引用。报告不得包含真实创作者结论。
4. 对返回任务运行 `validate`、`research-validate`、`report-validate`、`status`，均应通过。
5. `feishu-plan` 应只生成本地计划，含两个封面加三张原图，无视频、无云端写入。

## 第二层：独立依赖安装

1. 检查 Git、Python、Node/npm、FFmpeg/ffprobe。
2. 运行 `setup`，确认上游下载在新工作区 `dependencies/Spider_XHS`，Python环境也在其中。
3. 再次运行 `setup`，应显示复用且不自动升级。
4. `doctor` 的本机依赖检查应全通过，但 `online_validated` 仍为 false——它不是登录测试。
5. 在源码根目录用刚安装的上游 `.venv/bin/python` 运行 `-m unittest discover -s tests -v`。只用系统Python时图像运行时测试可能因缺Pillow而跳过；交付验收应使用完整环境，无跳过。

## 第三层：用户指定真实账号

首次建议一个包含图文与视频、样本量适中的公开账号。先少量验证，再新建正式最近10条批次。

- 用户提供目标并授权采集后 init/capture。扫码由用户完成；二维码位置来自命令输出。
- 中断后查看 status，明确 `--resume`。已下载素材不应重下，程序不切换浏览器。
- 核对置顶和实际发布时间、图文数量和全部原图、视频时长、评论范围、样本不足依据。
- 有视频时选择已有逐字稿或另行授权豆包ASR。图文必须逐张阅读。
- Agent完成研究文件后，验证、生成、打开本地报告，再确认结论与素材对应。

不把分页预算、验证码或网络中断当成账号作品不足。接口失败留存原因和任务路径，不删除会话、不自动切换渠道或重复收费。

## 第四层：可选增强

ASR先只验证一个已授权视频：提交ID持久化、查询续跑、时间戳、原稿校订。飞书先验证一个已授权作品：文字、封面与图文原图回读，确认没有视频附件。

把验收结果记录在**私人工作区**的 `reports/validation/`，包含系统与运行时版本、任务标识、成功/失败步骤和必要的脱敏错误；不要提交 Cookie、密钥、原始API响应或真实报告到公共源码。
